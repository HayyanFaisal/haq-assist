Technique

Retrieve the law, then check the supporting excerpts

✕

Plain LLM: answers from memory. Asked only to rephrase a question, Qwen3.5-9B invented a “Consumer Protection Act 2012”.

✕

Fine-tuning: bakes the law into weights that go stale with every amendment, and needs training data we don’t have.

✓

RAG with checks: the library updates without retraining; answers use only retrieved text, and quotes and numbers are checked in code.

+

For stories: the LLM writes statute-style search sentences (rights, remedy, offence: HyDE). Each is searched, and reviewed rights-card law is pinned.

SCRIPT: Why this technique? A plain language model answers from memory, and memory invents law. When we only asked Qwen to rephrase a question, it invented a “Consumer Protection Act 2012”; Punjab’s act is from 2005. Fine-tuning would bake the law into the model’s weights, which go stale with every amendment, and we have no large verified question-and-answer dataset to train on. So we use retrieval-augmented generation, with checks. The model may only use text we retrieve from the official library, and code checks every quote and number. In the lecture’s terms this is advanced, modular RAG: rewrite the question before retrieval, rerank after it, and reflect on the answer before showing it. The chart shows how we chose the search. Keyword search found the right section in the top five only 31 percent of the time, because people don’t use the law’s words. Rewriting into legal English took it to 71. Multilingual embeddings reached 88, two embedding models fused reached 94, and a reranker 98 percent. We tested 69 configurations. One more fix for real stories: the model writes sentences the way a statute would state the rule, and we search with those. That is HyDE. For “police won’t register my FIR”, the right section, CrPC 22-A, was not even in the top 200; phrased like a statute, it ranks first.
